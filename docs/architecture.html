System Architecture Reference

Factory Inventory Management

A Vue 3 single-page app talking to a FastAPI backend that serves entirely in-memory data. There is no database — every dataset is a flat JSON file, read once at boot and filtered in Python on each request.

Vue 3.4 + Vite 5 — :3000 FastAPI + Uvicorn — :8001 0 databases — 7 JSON files No auth — demo only
01 — Overview

What this system is

Built as a demo for a Claude Code workshop, it tracks factory inventory, orders, demand forecasts, backlog, and spending across multiple warehouses. Four shared filters — time period, warehouse, category, and order status — drive nearly every view. The whole backend is stateless between requests: nothing written through the API survives a restart, because nothing is written anywhere — it's re-read from server/data/*.json every time the process starts.

03 — Architecture

Request path, top to bottom

The whole system is five hops stacked vertically: a browser, a Vue SPA, a FastAPI process, an in-memory loader, and the JSON files it read once at startup. Nothing below the loader is ever written back to.

04 — Data Flow

Changing a filter, step by step

01

Filter changes in the UI

A user picks a warehouse, category, status, or month in FilterBar.vue, which writes to the module-level refs inside useFilters() — a singleton shared by every view, not a per-component instance.

02

View requests fresh data

The active view (e.g. Orders.vue) calls api.getOrders(filters), which builds a URLSearchParams and skips any filter left at 'all'.

03

Axios sends the request

GET http://localhost:8001/api/orders?warehouse=…&category=…&status=…&month=… — CORS is wide open (allow_origins=["*"]), so no preflight friction in dev.

04

FastAPI filters in Python

apply_filters() narrows by warehouse/category/status, then filter_by_month() matches a direct YYYY-MM or resolves a quarter (Q1-2025 … Q4-2025) against each order's order_date.

05

Pydantic validates the response

The filtered list is coerced through a response_model (e.g. List[Order]), which is also the single source of truth for the shape the frontend can rely on.

06

Vue stores it and derives the rest

The response lands in a raw ref (allOrders); every chart, total, and table row the template shows comes from a computed() built on top of it, never from mutating the raw ref directly.

06 — Key Patterns

Conventions worth knowing

Singleton composables

useFilters(), useAuth(), and useI18n() all hold module-level refs — calling the composable twice returns the same reactive state, not a fresh copy per component.

Raw refs, derived computeds

Views keep server responses untouched in refs (allOrders, inventoryItems) and compute everything else — totals, sorted lists, chart series — so a re-fetch is the only place state actually changes.

Locale-driven currency

useI18n() switches between en.js/ja.js; selecting ja also switches the currency formatter to JPY, falling back to English for any missing key.

RouteFiltersNotes
GET/api/restocking/recommendationsbudget (required), warehouse, categoryGreedy-by-urgency: ranks demand-forecast items by shortfall (forecasted_demand - current_demand), then fills the budget largest-shortfall-first. 400 if budget is missing or ≤ 0.

08 — Operating Notes

Things a cold reader should know before touching this

!
State doesn't persist. All data lives in Python lists loaded at import time — restarting main.py discards anything a POST endpoint changed and reloads straight from the JSON files.
!
CORS is wide open by design. allow_origins=["*"] is a dev-only convenience for the Vite server on a different port — it would need locking down before this touched a real deployment.
!
Auth is mock-only. useAuth() exists on the frontend for UI state; there's no backend session, token, or credential check behind it.
!
Tests run from server/, not tests/. uv run pytest ../tests/backend -v — tests/ has no pyproject.toml, so invoking pytest from there fails despite what the READMEs say.
